IRCC Tracker 安全诊断工具｜使用教程
===================================

一、哪个文件才是运行文件？
--------------------------

请双击：

点击运行IRCC查询.cmd

“使用教程.txt”只是说明文件，双击它不会进行查询。
“IRCC_Status_Check.ps1”是主程序，不需要直接打开或修改。


二、运行前准备
------------

1. 完整解压 ZIP，不要直接在压缩包中运行。
2. 建议放在本机非共享、非 OneDrive/Dropbox 同步目录。
3. 不要把账号、密码、UCI 或申请号写进脚本。
4. 本项目非 IRCC 官方工具，当前接口仍不稳定，不保证查询成功。


三、输入内容
----------

双击“点击运行IRCC查询.cmd”后，依次输入：

1. UCI
2. Application Number
3. Tracker 密码

UCI 只需要输入一次，同时作为 Tracker 登录用户名。

以下格式都可以：

12345678
1234-5678
1234567890
12-3456-7890

程序会自动删除连字符和空格，并检查最终结果是否为 8 位或 10 位纯数字。
如果格式不正确，程序会要求重新输入，不会把错误格式发送给服务器。

密码输入时不会显示文字或星号，这是正常现象。输入结束后窗口会自动清屏，避免截图保留个人资料。


四、查询过程
----------

程序依次执行：

1. Cognito 安全登录
2. 本地检查临时 ID Token
3. 读取账号申请列表
4. 精确匹配 Application Number
5. 查询申请详情

成功后，结果只显示在当前窗口，不生成 StatusCheck.txt，也不保存查询历史。


五、失败后的选择
--------------

第一次失败后会显示不含凭据的诊断信息，并提供：

R：手动重试一次
Q：退出

程序不会自动重试。选择 R 后只允许再尝试一次；第二次失败后必须退出。

不要连续反复重新运行，以免触发 IRCC 限流。


六、诊断信息可以分享什么？
------------------------

可以分享：

- 红色错误行
- 出错阶段
- HTTP 状态码
- Content-Type
- PowerShell 版本
- TLS、耗时和异常类型

不要分享：

- UCI
- Application Number
- Tracker 密码
- Token、Session 或 Authorization Header
- 请求体或响应正文
- 输入画面或未打码截图


七、关于 Security 节点
-------------------

“检测到 Security 历史节点”只表示返回数据中存在名为 Security 的内部节点。
它不等同于确认进入深度安调，也不能证明安调仍在进行或节点日期就是实际开始日期。


八、常见错误
----------

HTTP 401/403：登录、Token、权限或认证流程被拒绝。
HTTP 429：请求过多，请停止并等待。
HTTP 500/502/503：IRCC 服务端或网关暂时不可用。
underlying connection was closed：服务器或网关在返回 HTTP 响应前关闭连接。
non-JSON response：可能返回了维护页面。
Application Number 不匹配：输入编号不在当前登录账号的申请列表中。


九、退出与隐私
------------

关闭窗口后，本次凭据、Token 和查询结果不会由程序写入文件。
工具没有遥测、广告、Webhook、自动轮询或第三方数据上传。

如果以前使用过把密码写进脚本的旧版，请删除旧文件、回收站副本以及云端历史版本。
